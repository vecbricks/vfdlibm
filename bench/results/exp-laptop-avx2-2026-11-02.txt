# ExpBenchmark on the owner's laptop under -XX:UseAVX=2, 2 November 2026: before and after the fix
#
# LAPTOP NUMBERS, NOT HEADLINES. -XX:UseAVX=2 makes C2 compile as for an AVX2 host (GitHub's x86
# runners and the EPYC 7763 benchmark hosts): it clears the AVX-512 features, AVX512DQ included.
# The laptop's own datapath is 256 bits either way. Headline numbers come from the EPYC 7763.
#
# Before:      deb5d4e (exp's k through D2L and t through L2D)
# After:       ed95fb7 (k through D2I, t through I2D, the exponent add through I2L); only comments
#              changed in Exp.java since the run
# JDK:         OpenJDK 64-Bit Server VM (build 25.0.4.1+1-1-26.04.4-Ubuntu, mixed mode, sharing)
# CPU:         AMD Ryzen AI 9 HX PRO 370 w/ Radeon 890M
# Vector:      -XX:UseAVX=2 -XX:MaxVectorSize=32 (preferred species 256 bits)
# Kernel:      7.0.0-42-generic
# Load:        before: load average: 0.17, 0.82, 1.55 at start; 1.21, 1.09, 1.52 at end
#              after:  load average: 1.30, 1.22, 1.48 at start; 1.14, 1.19, 1.42 at end
#              re-run: load average: 0.87, 1.12, 1.30 at start; 0.99, 1.11, 1.28 at end
#              (24 logical cores)
# JMH 1.37:    -f 2 -wi 3 -w 2s -i 5 -r 2s -prof gc
#              -jvmArgsAppend "-XX:UseAVX=2 -XX:MaxVectorSize=32
#              -XX:CompileCommand=inline,io.github.vecbricks.vfdlibm.*::*"
#              (the body inlined into the loop, as Varka emits it)
# Command:     java --add-modules jdk.incubator.vector -cp <test classpath> org.openjdk.jmh.Main
#              "ExpBenchmark.(finish256|blended256|scalarStrictMath) <the options above>"
# Array:       1024 doubles; common = uniform [-20, 20]; mixed = one input in 16 replaced by NaN,
#              800, -750 or -708.5
# Not run:     512 bits (no 512-bit vectors under UseAVX=2, so software); 128 bits (no mask
#              operation lowers at two 64-bit lanes, see below; they box with or without the fix)
#
# Checks:
# - -XX:+UnlockDiagnosticVMOptions -XX:+PrintIntrinsics, before: VectorSupport::convert fails to
#   intrinsify with "not supported: op=cast#510/3 vlen2=4 etype2=double" (L2D) and "cast#512/3
#   vlen2=4 etype2=long" (D2L); C2 lowers those only with AVX512DQ. Both arms allocate 98304
#   B/op on common data. No other op of the body (long compares, shifts, adds, blends, mask casts
#   at four lanes) was refused.
# - After: the converts intrinsify, and every 256-bit arm allocates ~0 B/op on common data. A
#   first try took the int species from VectorSpecies.of, which C2 does not see as a constant
#   ("missing constant ... vlen_to=LoadI"), and still allocated 49152 B/op; Lanes.intSpecies
#   picks IntVector's constant species instead.
# - 128 bits under UseAVX=2, PrintIntrinsics: blend (useload), compare (usestore), mask cast,
#   mask broadcast and test are "not supported" at vlen=2 for double and long masks, so masked
#   128-bit code boxes on x86 regardless of this fix.
# - finish256 on mixed data allocates 52928 B/op: the per-lane finish's toArray/fromArray.
# - Re-run: on mixed data finish256 and blended256 are within 1.3x of each other after the fix,
#   so they were run again; the re-run's minimums are at the end.
#
