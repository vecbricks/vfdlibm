# LogBenchmark on the owner's laptop under -XX:UseAVX=2, 2 November 2026: three per-lane finishes
#
# LAPTOP NUMBERS, NOT HEADLINES. -XX:UseAVX=2 makes C2 compile as for an AVX2 host (GitHub's x86
# runners and the EPYC 7763 benchmark hosts): it clears the AVX-512 features, AVX512DQ included.
# The laptop's own datapath is 256 bits either way. Headline numbers come from the EPYC 7763; on
# exp, the laptop understated the cost of a boxing finish on mixed data (SKILLS.md, the log port).
#
# Commit:      the commit that adds this file (on ecd354c). FINAL is its Log.java. The two earlier
#              versions differ only in the finish arm's rare-lane code (described at each section)
#              and, for FIRST, in VFdlibm.log calling Log.log (the benchmark now calls Log.log
#              directly; the body is the same); every run measures Log.log and Log.logBlended.
# JDK:         OpenJDK 64-Bit Server VM (build 25.0.4.1+1-1-26.04.4-Ubuntu, mixed mode, sharing)
# CPU:         AMD Ryzen AI 9 HX PRO 370 w/ Radeon 890M
# Vector:      -XX:UseAVX=2 -XX:MaxVectorSize=32 (preferred species 256 bits)
# Kernel:      7.0.0-42-generic
# Load:        each run waited for a one-minute load average under 1.0 (24 logical cores; other
#              agents share the machine and the end loads show their return):
#              final:    0.85, 1.20, 1.69 at start; 1.44, 1.34, 1.65 at end
#              re-run:   0.78, 1.85, 1.83 at start; 1.10, 1.61, 1.75 at end
#              arrays:   0.87, 2.17, 2.44 at start; 1.02, 1.64, 2.17 at end
#              first:    0.99, 4.09, 4.17 at start; 1.03, 2.63, 3.58 at end

#              (the body inlined into the loop, as Varka emits it)
# Command:     java --add-modules jdk.incubator.vector -cp <test classpath> org.openjdk.jmh.Main
#              "LogBenchmark.(finish256|blended256|scalarStrictMath) <the options above>"
# Array:       1024 doubles; common = positive normals with binary exponents uniform over
#              [-30, 30] and random significands; mixed = one input in 16 replaced by 0.0, -1.5,
#              NaN, 1.0e-310 (subnormal) or +inf
# Not run:     512 bits (no 512-bit vectors under UseAVX=2, so software); 128 bits (no mask
#              operation lowers at two 64-bit lanes on x86, SKILLS.md; they box)
#
# Checks (-XX:+UnlockDiagnosticVMOptions -XX:CompileCommand=PrintIntrinsics,...::*, -f 1):
# - Common data, both arms: every VectorSupport call, the L2I, I2L and I2D converts and the
#   int-to-double mask casts included, "late inline succeeded"; nothing "not supported",
#   "missing constant" or "unbox failed". Both arms allocate ~0 B/op.
# - FIRST, mixed data: "Log::finishPerLane (59 bytes) failed to inline: NodeCountInliningCutoff";
#   the refused call takes x, result and the mask as heap objects: 51648 B/op.
# - SECOND, mixed data: the call is still refused, but takes arrays and a long: 5184 B/op, the
#   toArray/fromArray arrays.
# - FINAL, mixed data: no finish call; lane(i) and withLane(i, v) in the body lower to extract and
#   insert, with nothing refused at 256 bits: ~0 B/op.
#
# Decision: VFdlibm.log is the finish arm (Log.log). FINAL against the blend at 256 bits, by
# minimums over both runs: faster on common data by about 1.18x and level to 1.05x faster on
# mixed data. Both ratios are under 1.3x, so the pair was re-run; the direction held.
#
