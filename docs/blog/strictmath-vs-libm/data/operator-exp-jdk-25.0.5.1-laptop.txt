# VectorOperators.EXP against StrictMath.exp and Math.exp, on Gen.java's 200,000 inputs

A laptop's reading, not a benchmark host's: another CPU, JDK or set of flags may give other
counts, and here the counts of the compiled operator differ between species. No timing: this
file counts bits only.

What was run and why: the post says "I have not measured how often VectorOperators.EXP differs
from StrictMath". ../OperatorExp.java computes DoubleVector.lanewise(VectorOperators.EXP) over
Gen.java's inputs (x in [-700, 700), java.util.Random seeded 7: the same 200,000 doubles,
checked against Gen.java's first column; Gen.java and rounding.py are in the blog's pull
request, #169) at one species per JVM, and compares each lane by Double.doubleToRawLongBits with
StrictMath.exp and with Math.exp, one line per pass. Each run without -Xint is given 30 passes,
so that the change from the interpreter to C2 shows; the -Xint runs are given 3.
../operator_rounding.py then reads the last pass's differing lanes (dump-<bits>.txt, not kept:
OperatorExp.java writes them again) and says which of the two results is correctly rounded. The
commands below ran in docs/blog/strictmath-vs-libm, one at a time, with -Xmx512m added.

  and 614f7af), on vfdlibm at 20df30f (origin/main); the program uses no vfdlibm code

-XX:+UnlockDiagnosticVMOptions -XX:+PrintIntrinsics, C2 printed
"jdk.internal.vm.vector.VectorSupport::libraryUnaryOp (35 bytes) (intrinsic) late inline
succeeded" for the operator's call, so the warm passes run the intrinsic, not the Java fallback.

Math.exp differs from StrictMath.exp on 19,452 inputs in every run and every pass. Under -Xint,
and in passes 2 and 3 of each run without it, the operator's lanes equal Math.exp's on every
input. Pass 1 of those runs already differs from Math.exp on 671 to 5,828 lanes; from the 4th,
5th or 6th pass, by run, every pass's line is the same to the 30th. Every differing lane is 1
ulp from StrictMath.exp. Where the warm operator and StrictMath.exp differ, the correctly
rounded result is the operator's on 19,053 of the 19,439 lanes at 128 and 256 bits (StrictMath's
on 386), and on 15,768 of the 21,255 at 512 bits (StrictMath's on 5,487); neither, and too close
to call, on none. The dump files of the 128- and 256-bit runs, with and without -XX:UseAVX=2,
are the same bytes, and so are those of the two 512-bit runs.
